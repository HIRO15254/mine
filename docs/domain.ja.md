# ドメインの決まり

Mine が扱うデータと、その振る舞いの決まりをまとめたものです。コードを変えてこの決まりが変わるときは、同じ push でここも直します。表の定義は `packages/db/src/schema/`、振る舞いは `packages/api/src/` にあります。

## 値の表し方

| 種類 | 表し方 | 例 |
|---|---|---|
| 日付 | 利用者の暦での `YYYY-MM-DD` の文字列 | `2026-11-12` |
| 時刻（瞬間） | UTC のエポックミリ秒の整数 | `1794450000000` |
| 予定の時刻 | `HH:MM` の文字列（タスクの `scheduledTime` だけ） | `14:30` |
| 金額 | 円の整数 | `3500` |

`created_at` と `updated_at` だけは Drizzle の `timestamp` モードで、エポック秒で保存されます。

### タイムゾーン

サーバーは「今日が何日か」を自分で決めません。日付が要る手続きは、呼ぶ側から `today` や `timeZone` を受け取ります。

- Web はブラウザのタイムゾーンを送ります。
- MCP サーバー（Claude）は `Asia/Tokyo` に固定です。
- `/v1` の API は時刻だけを扱い、日付は扱いません。

ローカルの日付を `toISOString().slice(0, 10)` で作ってはいけません（UTC の日付になり、日本では午前 9 時まで前日になります）。Web では `apps/web/src/lib/tasks.ts` の `todayKey()`、サーバーでは `packages/api/src/time/` の `localDay()` と `startOfDayIn()`、日付の足し引きは `packages/api/src/tasks/dates.ts` を使います。

## タスク

### 3 つの日付

どれも任意です。

| 項目 | 呼び方 | 意味 |
|---|---|---|
| `startDate` | 最速実行可能日 | この日より前は「今日」に出さない |
| `scheduledDate` | 予定日 | やるつもりの日。`scheduledTime` があればカレンダーにも置く |
| `deadline` | 締め切り | 遅れてはいけない日 |

### 優先度とラベル

- 優先度は 1 がいちばん高く、4 が既定です。
- ラベルは利用者ごとに名前が一意です。
- `next` という名前のラベルは「次にやること」の印で、日付に関係なく「今日」に出ます。

### ビュー

| ビュー | 入る条件 |
|---|---|
| 今日（`today`） | 最速実行可能日が来ていて、予定日か締め切りが今日以前、または `next` ラベルが付いている |
| インボックス（`inbox`） | プロジェクトが無い |
| 近日（`upcoming`） | 予定日か締め切りが明日から 14 日後まで |
| すべて（`open`） | 未完了のすべて |

Web のタスク画面はビューを指定しないと近日を開きます。ホームの「今日やるタスク」からは今日のビューへ移ります。

並び順は、優先度、いちばん早い日付（予定日、無ければ締め切り）、作った順です。判定は `packages/api/src/tasks/views.ts` にあり、Web も楽観的更新のために同じ関数を使います。

### 繰り返し

繰り返しのタスクは 1 行のままです。完了すると `task_completion` に 1 回分の記録を残し、タスクの日付を次の回へ進めます。完了を取り消すと、記録しておいた日付に戻します。

- 単位は日・週・月で、間隔は 1 から 365 です。週は曜日を、月は日（1 から 31、月末で切り詰め）を指定できます。
- 基準は 2 つあります。`schedule` は予定から数え、遅れていても過去の日には戻りません。`completion` は完了した日から数えます。
- 数え始めは予定日、無ければ締め切りです。3 つの日付は同じ日数だけ動きます。
- 月の繰り返しで日の指定が無いときは、最初に完了したときの日に固定します。そうしないと 31 日のタスクが 2 月に 28 日へ動いたまま戻らなくなるためです。
- 完了は、読んだときの状態のままのタスクにだけ効きます。同じ完了の依頼が 2 回届いても、2 回進むことはありません。

## プロジェクト

- プロジェクトは木構造で、タスクと時間の記録の両方が使います。色はプリズムの 5 色（`chart-1` から `chart-5`）です。
- 名前は親が違えば重なってよく、外からは `大学 / 研究` のような経路で指せます。名前だけで複数に当たるときは、候補を返して断ります。
- 終わったプロジェクトはアーカイブします。時間の記録があるプロジェクト（子孫を含む）は削除できません。削除すると記録からプロジェクトと単価が外れてしまうためです。
- 記録の無いプロジェクトを削除すると、子プロジェクトも消え、タスクはプロジェクト無しになります。

## 時間の記録

- 記録は開始と終了の時刻を持ちます。終了が空の記録が「計測中のタイマー」で、利用者ごとに 1 つだけです（データベースの部分一意インデックスで守っています）。
- タイマーを始めると、計測中のものを止めてから新しい記録を作ります。この 2 つは 1 回のバッチで行います。
- タスクから始めた記録は、指定が無ければタスクの題名とプロジェクトを引き継ぎます。
- 記録には請求対象かどうか（`billable`）があり、既定は対象です。

### 単価と集計

- 単価は 1 時間あたりの円で、プロジェクトごとに「この日から」の日付を付けて持ちます。
- 自分の単価が無いプロジェクトは、いちばん近い親の単価を使います。どこにも無ければ金額は出しません。
- 集計は、日をまたぐ記録をローカルの 0 時で分け、それぞれの日に計上し、その日の単価で計算します。金額は最後に円へ丸めます。
- 計測中の記録は、今の時刻までを数えます。

## カレンダー

- 予定は Google カレンダーが正です。Mine は予定を Google カレンダーに直接書き込み（作成・変更・削除）、自分では持ちません。
- 書き込めるのは、自分が「オーナー」か「変更可能」のカレンダーだけです（祝日のカレンダーなどは読むだけ）。
- 繰り返しの予定を変えたり消したりすると、その回だけが変わります。繰り返し全体を変えるときは Google カレンダーで行います。
- どのカレンダーを表示するかだけを Mine が持ちます（`calendar_preference`）。設定が無いカレンダーは Google 側の選択に従います。
- 今進行中の予定を記録していないとき、「今日」の画面がその予定の開始時刻からの記録を勧めます。同じ題名の記録があるか、10 分以上重なる記録があれば、記録済みとみなします。

## Claude のスレッド

Claude が MCP 経由で自分の会話の状況（作業中・あなた待ち・完了）を報告し、「今日」の画面に並びます。リンクは https だけを受け付けます。

## 利用者とトークン

- ログインは Google だけで、`ALLOWED_EMAILS` に載っているメールアドレスだけがアカウントを作れます。一覧から外すと、そのアカウントはすぐに使えなくなります。
- 個人用 API トークンは発行時に一度だけ表示し、保存するのは SHA-256 のハッシュだけです。
- Claude などのアプリは Mine 自身の OAuth サーバーで接続します。アクセストークンと更新トークンは更新のたびに入れ替わり、接続を削除すると使えなくなります。
- すべての行は利用者に結び付いていて、すべての問い合わせは利用者で絞り込みます。

# Web app guide

Adds to the root `AGENTS.md`, which holds the UI rules, the test conventions and the shipping rules.

## Where things go

- `src/routes/`: one file per route (TanStack Router, file based). A route file reads the URL, picks the data and lays out the page; anything with its own state or more than a few dozen lines goes to `src/components/<feature>/` (the calendar route is the model: `WeekPlanner` holds the planner). `_app.tsx` is the signed-in shell and guard; screens live in `_app/`. `routeTree.gen.ts` is generated by the Vite plugin, never edited.
- `src/components/<feature>/`: a feature's components, its data hooks (`use-tasks.ts`, `use-time.ts`) and its form state (`task-draft.ts`, `entry-draft.ts`).
- `src/components/ui/<name>/<name>.tsx`: ports of Mine Design System components. A new primitive is ported from the design system, not invented here.
- `src/components/app-shell/`: the sidebar, the tab bar, `Page` (every screen's header and body), the error screens, and the pieces every screen shares: `LoadingBlock`, `EmptyState`, `WeekNavigation`.
- `src/components/form-sheet/`: `FormSheet` and `useSheetState`, which every editor uses.
- `src/lib/`: everything that is not a component or a hook. Mostly logic without React or the DOM (dates, grouping, parsing), tested with `.test.ts` in the node project, where the time zone is pinned to `Asia/Tokyo`; and the clients (`trpc.ts`, `auth-client.ts`).
- `src/hooks/`: hooks that are not tied to one feature (`useToday`, `useIsDesk`, `useOnline`, `useNow` for a ticking clock, `useWeek` for the screens that show one week).
- `src/lib/trpc.ts`: the query client and the tRPC client. Nothing else creates one.

Before writing a helper, look for it; these exist once and are meant to be reused:

- Types come from the API (`RouterOutputs[...]`, as `Task`, `Project`, `TimeEntry`, `DisplayEvent` in `src/lib/`), never from a hand-written interface. Rules the server also applies are imported from `@mine/api` (`inView`, `compareTasks`, `projectPath`), not written again.
- Time: `formatClock(ms)` is the one way an instant is shown as `HH:MM`; `formatTime(minutes)` writes a task's time of day; `useNow(everyMs)` is the one ticking clock.
- Projects: `findProjectByName()` reads a typed `#name`; `<ProjectOptions>` fills a project picker; `projectPath()` builds "大学 / 研究".
- Controls: `useControlSize()` gives the size of form controls for the layout; do not write `isDesk ? "default" : "xl"`.
- A section that is loading shows `<LoadingBlock />`; one with nothing to show, or that failed, shows `<EmptyState>`.

## Adding a screen

1. Create `src/routes/_app/<name>.tsx` with `createFileRoute("/_app/<name>")`, and wrap the content in `Page` with a Japanese title. Validate search parameters in `validateSearch`.
2. Add it to `src/components/app-shell/navigation.ts` when it belongs in the navigation: widen the `to` union and add the item. The tab bar holds five items; a sixth needs a design decision first.
3. Add a row to `screens/screens.ts` and fixtures for its queries to `queries` in `screens/fixtures.ts`. `bun run screens -- --only <name>` names every query it could not answer.
4. Draw or update the artboard on the Mine UI canvas, or leave a note there (see the `ui-design` skill).

## Reading and writing data

- Read with `useQuery(trpc.<router>.<procedure>.queryOptions(input))`. Put a query used by more than one component into the feature's `use-*.ts` hook.
- Write through hooks in the feature's `use-*.ts`. Changes to tasks and the timer are optimistic: change the cached lists first (`components/tasks/optimistic.ts`), roll back and show a message when the server refuses, then invalidate. For tasks that is `useCreateTask`, `useUpdateTask` and `useDeleteTask` in `use-tasks.ts`; pass what to say on failure and do not write another `onMutate`.
- A mutation without its own `onError` gets the common toast from the `MutationCache` in `src/lib/trpc.ts`; add `onError` only to say something more specific. `isConflict(error)` tells a duplicate or refused change apart.
- Mutations do not wait for a connection (`networkMode: "always"`): offline they fail at once and the input stays or comes back. Never queue a write for later.
- Loaded data is saved for a week for offline starts (`src/lib/offline.ts`). When a procedure's output changes shape, raise `CACHE_VERSION` so old copies are dropped.
- The current day comes from `useToday()` or `useTodayDate()`, and the time zone from `currentTimeZone()`; pass them to procedures that take `today` or `timeZone`.

## Forms and overlays

- An editor is a `FormSheet`: a dialog at `desk` and a drawer below it. Keep its state in a draft module beside it, with the conversion to and from the API shape tested in a `.test.ts`. Whoever opens it holds a `useSheetState()` and passes its `key`, `open`, `setOpen` and `value`.
- Deleting asks through `ConfirmDeleteButton`.
- Feedback after an action is a `sonner` toast; errors inside a form show in the form.

## Tests

- A component test (`.test.tsx`) mocks `@/lib/trpc` with `src/__tests__/test-api.ts` and starts with `beforeEach(() => api.reset())`, which gives a fresh database. Module-level state in components (such as the timer's unsent text) still leaks between tests, so do not rely on it.
- Seed through `api.caller` (`await api.caller.project.create({ name: "仕事" })`) and pass components what the app would have loaded: `await api.client.project.list.query()`. Use the ids the server returned, never invented ones.
- Prefer asserting on the result (`await api.caller.task.list(...)`) over the call. `api.calls(path)` is for "nothing was sent" and for input the result does not show.
- `api.stub(path, answer)` answers a procedure without the server, for data the database cannot hold (calendar events); `api.fail(path, delayMs)` makes it fail.
- Call `freezeNow()` when a test shows or sends a time. It stops `Date` only, so waiting and user events still work; the server's clock follows it unless the test sets `api.clock.now`.
- `makeTask()`, `makeProject()` and `makeLabel()` from `task-fixtures.ts` build rows for tests of pure logic and of components that take everything as props.
- `useDesktopLayout()` from `src/__tests__/render.tsx` switches a test to the desk layout.
